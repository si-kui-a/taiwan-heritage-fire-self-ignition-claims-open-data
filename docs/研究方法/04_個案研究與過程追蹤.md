# 個案研究與過程追蹤（Case Study and Process Tracing）

建立：2026-09-30｜層次：研究設計／分析方法｜常用於：政治學、社會學、歷史社會學、政策研究

**一句話**：在一個或少數個案內，依時間順序追出從原因到結果的每個環節，並逐一檢驗每個環節的證據。

## 主要文獻

Beach & Pedersen（M13）系統整理過程追蹤：把因果機制拆成一連串環節，每個環節都要有可觀察的證據，並說明證據對假說的支持強度。

## 過程追蹤的三種用途

| 類型 | 目的 |
|---|---|
| 理論檢驗 | 已有理論提出的機制，在個案中是否真的存在 |
| 理論建構 | 從個案中找出尚未被理論描述的機制 |
| 解釋結果 | 對單一重要事件提出足夠完整的解釋 |

## 證據檢驗的四種類型

依證據對假說是「必要」或「充分」來分類（常見於過程追蹤文獻）：

| 檢驗 | 通過代表什麼 | 沒通過代表什麼 |
|---|---|---|
| 隨風稻草（straw in the wind） | 稍微支持 | 稍微削弱 |
| 圈環檢驗（hoop） | 假說還活著，但尚未確認 | 假說被排除（證據是必要條件） |
| 冒煙的槍（smoking gun） | 假說被強力支持（證據是充分條件） | 假說不一定錯 |
| 雙重決定（doubly decisive） | 確認假說並排除對手 | 排除假說 |

## 操作步驟

1. **寫下機制**：把假說拆成環節，例如「事件 A → 行動者的決定 B → 制度結果 C」。
2. **列出每個環節應該留下的痕跡**：文件、公告、會議紀錄、報導、時間順序。
3. **列出對立解釋**：同樣的結果還可能由哪些過程造成，各自應該留下什麼痕跡。
4. **建立時序表**：每個事件附日期與來源。
5. **逐一檢驗**：每個環節記下支持與反對的證據，以及證據屬於哪一種檢驗。
6. **下結論**：說明哪些環節有強證據、哪些只是推論，對立解釋被排除的程度。

## 個案選擇

- 事先寫定選擇規則，例如「最常被提到的個案」加上「條件相近但結果不同的對比個案」（見[巢狀分析](03_巢狀分析.md)）。
- 對比個案用來檢查某個條件是否真的必要：條件相同卻沒有出現結果，表示還有其他因素。

## 品質判準

- 每個環節都能追回原始來源。
- 對立解釋與主要假說用同樣的標準檢驗。
- 證據不足的環節直接寫明，不以推論填補。

## 常見誤用

| 誤用 | 問題 |
|---|---|
| 只寫支持假說的證據 | 變成說故事，不是檢驗 |
| 以時間先後代替因果 | A 在 B 之前，不代表 A 造成 B |
| 從單一個案推論到全體 | 過程追蹤檢驗的是個案內的機制，推論範圍要另外說明 |

## 應用前可以自問的問題

1. 我要檢驗、建構機制，還是解釋單一結果？
2. 假說的每個環節應該留下什麼可以查到的痕跡？
3. 對立解釋有哪些？它們會留下什麼不同的痕跡？
4. 哪些證據屬於圈環檢驗，哪些屬於冒煙的槍？
